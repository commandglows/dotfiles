# Bug Record: BUG-2026-08-31-001

## Summary

- Title: Windows installer leaves Yazi without its declared plugin
- Current status: `closed`
- Severity: `medium`
- Owner: Diane
- Next step: Keep automatic Yazi package installation covered by the Windows installer contracts.

## Reproduction

- Preconditions: Install the versioned Yazi configuration on Windows without separately requesting plugin installation.
- Steps:
  1. Run the Windows dotfiles installer with Yazi selected.
  2. Start `yazi` or `y`.
  3. Observe the Lua runtime failure while loading `git.yazi`.

## Expected Behavior

- Selecting Yazi installs the packages declared by its versioned `package.toml`, leaving Yazi runnable immediately.

## Observed Behavior

- The normal installer linked the configuration but ran `ya pkg install` only when `-InstallYaziPlugins` was supplied, so `git.yazi` could be absent while `init.lua` required it.

## Evidence

- The installed configuration declared `yazi-rs/plugins:git`, while the local `plugins/git.yazi` directory was absent.
- The focused dry-run regression initially failed with `Yazi selection did not plan plugin installation`.
